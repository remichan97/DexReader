# DexReader Design Tokens

**Last updated**: October 2026 (v1.16.0)
**Source of truth**: [`src/renderer/src/assets/tokens.css`](../../src/renderer/src/assets/tokens.css)

---

## Overview

This document describes the design tokens (colours, typography, spacing, radii, shadows, motion) that style DexReader's own components and views. The code blocks below are copied from `tokens.css`; if they disagree with the file, the file wins.

### Relationship to the Fluent 2 theme

Since v1.16.0 the shared components are Fluent 2 wrappers, so there are two token layers:

- **`--win-*` / `--space-*` / `--radius-*` CSS custom properties** in `tokens.css`. These style DexReader's own components and views, are switched by `data-theme`, and the accent is set at runtime on `--win-accent`.
- **Fluent theme tokens** (`colorNeutralBackground1`, `colorBrandBackground` and so on) generated by `createDexReaderThemes(accentColor)` in `src/renderer/src/theme/fluentTheme.ts`. Its neutral backgrounds, foregrounds and strokes are pinned to the palette below so Fluent surfaces match the rest of the app, and the brand colours are derived from the same accent.

When changing a colour, update `tokens.css` and check `fluentTheme.ts` so the two layers stay aligned.

---

## Theme switching

`document.documentElement.dataset.theme` is set to `light` or `dark` by `useStartupTheme` (at startup) and `AppShell` (whenever the resolved theme changes, whether from the user's theme setting or the system theme, which arrives via the `theme-changed` IPC event sent from `src/main/theme.ts`). The theme-dependent tokens live under `:root[data-theme='light']` and `:root[data-theme='dark']`, so they only apply once the attribute is set on the root element.

The reader is the exception: it sets `data-theme` on its own `.reader-view` element from the reader theme setting, and nests its own `FluentProvider` so Fluent components follow it.

### Accent colour

The accent is chosen by the user (or follows the system) and applied by `applyAccentColor` in `src/renderer/src/utils/accentColor.ts`, which sets three properties on the root element, overriding the defaults in `tokens.css`:

- `--win-accent`: the chosen colour
- `--win-accent-hover`: the colour darkened by 10%
- `--win-text-on-accent`: black or white, whichever reads better on the accent

The same value feeds `createDexReaderThemes`, which regenerates the Fluent brand ramp.

### Typography scale

The base styles in `tokens.css` apply the following to headings; everything else sets its size explicitly from the `--win-font-size-*` tokens.

| Element / token | Size | Notes                                           |
| --------------- | ---- | ----------------------------------------------- |
| `h1` / header   | 28px | Bold (700), line height 1.2                     |
| `h2` / title    | 20px | Bold (700), line height 1.2                     |
| `h3` / subtitle | 16px | Bold (700), line height 1.2                     |
| Body            | 14px | Regular (400), line height 1.5 (`body` default) |
| Caption         | 12px | Labels, hints, metadata                         |

### Spacing

Spacing uses a 4px base unit (`--space-1` is 4px). Prefer the `--space-*` scale over literal pixel values. `--padding-input` and `--padding-button` are the only semantic spacing tokens.

### Motion

`--duration-fast` (150ms) is for quick feedback and `--duration-normal` (300ms) for standard transitions. `--ease-spring` overshoots slightly and is only used by the reader's page fade-in, end-of-chapter slide-up and navigation indicator. The `--transition-*` tokens are shorthand values for the `transition` property, for example `transition: var(--transition-color)`.

### Layering

Only `--z-toast` is defined. Most components use literal z-index values and Fluent manages the stacking of its own popups, dialogs and toasts. See [Layering](../architecture/layout-specification.md#layering-z-index) in the layout specification for the layers in use.

## Surface effects

There is no Mica or acrylic material: the window uses an opaque `--win-bg-base` background and the sidebar is a solid `--win-bg-card` surface. A handful of overlays use a plain `backdrop-filter: blur(...)` directly in their own stylesheet: the reader's zoom and page-navigation indicators, the Gatekeeper unlock overlay, the Manga Detail header, the Settings header, and the MangaCard hover overlays. There is no shared token for this.

## Adding, changing or removing a token

1. Define a theme-dependent token in **both** the light and dark blocks. Put theme-independent values in the shared `:root` block.
2. Reference it with `var(--token-name)`. An undefined token resolves to nothing without any error, so check the name against `tokens.css`.
3. For colour changes, check `fluentTheme.ts` (see above).
4. Before removing one, search for it with `var(--token-name` across `src/renderer`. Tokens set from JavaScript (the three accent properties above) have no entry to find in the CSS usage.
5. Update this document.

### Naming convention

**Format**: `--{category}-{property}-{variant}`, for example `--win-bg-card`, `--win-text-secondary`, `--shadow-md`.

## History

The post-migration clean-up (v1.16.x) removed tokens nothing referenced: the component tokens (`--progress-*`, `--ring-*`, `--toast-*`, `--sidebar-*`), the acrylic pair, the unused background, border, text and state variants (`--win-bg-overlay`, `--win-bg-input*`, `--win-border-active`, `--win-border-disabled`, `--win-text-placeholder`, `--win-accent-dark`, `--win-accent-active`, `--win-accent-disabled`, `--win-success-hover`, `--win-warning-tint`, `--win-info-tint`), the semantic spacing and margin tokens, the z-index scale other than `--z-toast`, and the touch-target, focus-outline, `--duration-instant`/`--duration-slow`, `--ease-in` and single-property transition tokens. The original design intent for the component tokens was: progress bar 6px (4px compact), progress ring 24/48/64px with a 3px stroke, toast 320-480px wide with an 8px radius, and sidebar 240px expanded / 48px collapsed (the sidebar is now 80px wide).
